# ربط Visibly بمحفظتي برو — مرحلة مراجعة المسودات

الموقع الحالي يحتوي بالفعل على المدونة في `site/articles/`، مع 10 مقالات وخريطة موقع. لا ننشئ مسار `/blog/` مكررًا ولا نغيّر روابط المقالات الحالية.

## ما تم تجهيزه

سحب المقالات من API الرسمي إلى ملفات JSON للمراجعة. الملف الناتج يبقى خارج `site/`، ولا ينشر أي مقالة ولا يعدّل التطبيق أو المقالات الحالية. التشغيل يدوي، ولا يوجد اشتراك أو جدولة مدفوعة ينشئها هذا التعديل.

## الإعداد من متصفح الموبايل

1. داخل حساب Visibly افتح Connect Site، أضف `https://mohafzatypro.com`، وأنشئ مفتاح API. لا تختَر تكامل WordPress لموقع HTML.
2. افتح مستودع GitHub في المتصفح. استخدم «عرض سطح المكتب» عند الحاجة.
3. من Settings → Secrets and variables → Actions → Secrets أضف Repository secret باسم `VISIBLY_API_KEY` وضع المفتاح فيه. لا ترسله في المحادثة أو تحفظه في ملف.
4. من تبويب Variables أضف Repository variable باسم `VISIBLY_SITE_ID` بقيمة رقم الموقع في Visibly. لو الرقم مش ظاهر، يمكن معرفته من الاستجابة الموثقة لـ `GET /api/v1/sites`؛ لا تستخدم رابط الموقع بدل الرقم.
5. بعد دمج طلب التعديل، افتح Actions → Fetch Visibly drafts for review → Run workflow. التشغيل من الفرع الرئيسي؛ لا تضغط تشغيل على فرع غير موثوق مع المفتاح.
6. بعد النجاح افتح التشغيل وحمّل `visibly-review-...` من Artifacts. تظل الحزمة متاحة 7 أيام. اعتبر الملفات محتوى غير موثوق، واقرأها كنص فقط. لا ترفع الحزمة إلى الموقع العام.

## قبل أول نشر

- راجع العربية وصحة وصف البرنامج، وأي رسوم أو حدود مالية مقابل المصادر الرسمية.
- افحص الروابط الخارجية وشروط شبكة backlinks. يحتفظ الاستيراد بالنص والروابط المحمية كما وردت ولا يعدّلها في Visibly.
- حوّل المقال المعتمد إلى قالب المقالات الحالي، ونظّف HTML وفق قائمة سماح قبل إدخاله في صفحة عامة.
- أضف بطاقة في `site/articles/index.html` ورابطًا فريدًا وcanonical في `site/sitemap.xml`، ثم اختبر الروابط والموبايل في معاينة Cloudflare.
- لا توجد في هذا التعديل آلية نشر تلقائي أو تحويل HTML إلى صفحات: هذه مرحلة تجهيز الاتصال ومراجعة المحتوى، وتأتي مرحلة النشر بعد مراجعة أول مسودة حقيقية.

## التحقق وحدود التجربة

`python -m unittest discover -s tests -p 'test_visibly_drafts.py' -v`

الاختبارات تغطي منع حقن المسارات، الصفحات المتعددة، تطابق أرقام المقالات، الصفحات المكررة، ورفض تحويل طلبات الشبكة حتى لا يتسرّب المفتاح. لا تختبر اتصال حساب حقيقي بدون مفتاح ورقم موقع. يتوقف الاستيراد عند الأخطاء ولا يكتب تصديرًا جزئيًا بسبب أخطاء API. لا يطبع نصوص الاستجابات أو تفاصيل المفاتيح في السجلات.

المرجع: https://www.heyvisibly.com/developers و https://www.heyvisibly.com/api/v1/openapi.json
